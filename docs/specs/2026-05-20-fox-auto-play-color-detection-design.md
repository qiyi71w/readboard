# 野狐自动落子棋色识别设计

日期：2026-05-20

## 背景

readboard 现有自动落子依赖主界面里的 `执黑` / `执白` 单选项。用户需要在野狐对局开始前手动确认自己执哪一方，否则 `play black ...` / `play white ...` 可能不会发送，或发送错误棋色。

本设计只针对：

- `野狐`
- `野狐(后台落子)`

其它平台先保持现状。

本设计已核对：

- `docs/DEVELOPMENT.md`
- `docs/specs/2026-04-21-readboard-fox-title-status-design.md`
- `docs/specs/2026-05-04-sync-session-outbound-send-phase3.md`

相关约束：

- 不新增独立高频 Fox 标题或窗口轮询通道。
- 不改变 readboard 与 LizzieYzy-Next 的 wire protocol。
- `play black ...` / `play white ...` 仍是唯一自动落子棋色输出。
- 识别失败时宁可不自动落子，不猜测棋色。

## 目标

- 让用户可以选择 `自动`，由 readboard 在野狐对局里识别自己是黑棋还是白棋。
- 保留手动 `执黑` / `执白` 作为最高优先级。
- 第一次使用自动模式时，让用户确认自己的当前玩家行身份，并可选择本次使用或保存后持续使用。
- 后续自动模式尽量免打扰；识别失败或需要换身份时给清楚状态和重新选择入口。

## 非目标

- 不做观战身份识别；只把 Fox 标题里的 `观战中` 作为禁止自动落子的安全条件。
- 不从棋盘黑白子数量反推用户身份。
- 不为了识别昵称引入未经确认的大型 OCR 或外部运行时依赖。
- 不修改 LizzieYzy-Next 的协议解析或同步逻辑。
- 不支持非野狐平台自动识别棋色。

## UI 设计

把现有自动落子棋色单选项调整为三选一：

- `执黑`
- `执白`
- `自动`

行为：

- `执黑`：保持现有行为，发送 `play black ...`。
- `执白`：保持现有行为，发送 `play white ...`。
- `自动`：只在 Fox sync mode 下尝试识别当前用户棋色。

自动模式旁增加只读状态文本和 `身份...` 按钮。状态文本建议文案：

- `自动：已识别执黑`
- `自动：已识别执白`
- `自动：未配置身份`
- `自动：未识别玩家行`
- `自动：未识别棋色`

状态文本只展示当前结果，不改变自动落子条件。`身份...` 按钮只在 `野狐` / `野狐(后台落子)` 下可用，用于重新选择当前会话身份、保存身份或清除已保存身份。

## 首次自动确认

当用户第一次选择 `自动`，且没有当前会话身份、也没有已保存野狐身份时，弹出“选择玩家行”窗口。用户也可以之后通过主界面的 `身份...` 按钮重新打开。

窗口内容：

- 当前 Fox 右侧玩家列表中的可见玩家行候选；实测观战房可能显示 4 行，不假设固定只有 2 行。
- 每个候选显示整行截图预览，让用户直接看名字、棋子、段位等信息判断哪一行是自己。
- 不提供手动昵称输入框；野狐昵称文本当前不可稳定读取，手动输入也不参与匹配，保留只会误导。

窗口操作：

- `本次使用`：只在当前 readboard 进程中使用所选玩家行身份。
- `保存并使用`：保存玩家昵称字形指纹，并立即用于当前进程。
- `清除保存`：清除长期保存的身份；当前进程里临时选过的身份不通过参数设置管理，用户可直接点 `身份...` 重新选择。
- `取消`：不改变当前身份。

保存内容：

- 玩家昵称字形指纹，用于文本读取不可用时匹配同一个昵称区域。

不使用“以后不再提醒”这种反向开关。参数设置里不放 Fox 自动身份按钮，避免临时身份和长期保存身份分散到两个入口。

## 识别策略

识别流程只在现有 Fox 窗口绑定和同步生命周期内运行，不新增独立轮询线程。

### 实测结论

2026-05-20 在当前野狐客户端实测：

- 顶层窗口标题可通过 `GetWindowText` 读取。
- 右侧 `CRoomPlayerListPanel` 存在，但玩家昵称没有通过 `GetWindowText`、UI Automation、MSAA 或标准 `SysListView32` item 暴露出来；相关 ListView 的 item count 为 0。
- `PrintWindow` 对当前野狐顶层窗口返回黑图，不能作为第一版后台截图依据。
- 可见窗口截图可以稳定截到右侧玩家列表；保存的昵称字形指纹跨房间匹配有效。用上一房间 `鳕鱼の让子` 的昵称区域匹配另一房间 4 行玩家列表时，正确行得分 `0.91`，其它行最高 `0.28`。

因此第一版主路径使用用户确认过的昵称字形指纹匹配当前可见玩家行。OCR 和手动昵称文本不作为第一版依赖。

触发时机：

- 用户选择 `自动`
- 开始一键同步
- 开始持续同步
- Fox 房间上下文变化
- 当前自动识别状态为未知时，按现有采样节奏节流重试

步骤：

1. 确认当前模式是 `野狐` 或 `野狐(后台落子)`。
2. 确认当前 Fox 窗口绑定有效，并且标题状态是 `对弈中`；`观战中` 一律返回未知，不自动落子。
3. 定位右侧玩家列表区域。
4. 读取可见玩家候选行。
5. 用当前会话身份优先、已保存身份其次的昵称字形指纹匹配玩家行。
6. 只有唯一候选超过置信度阈值，并且领先第二候选足够多，才承认匹配。
7. 在匹配到的玩家行附近识别黑/白棋子图标。
8. 得出 `black` 或 `white`。

失败处理：

- 标题为 `观战中`：状态为 `自动：观战中`。
- 匹配不到玩家行：状态为 `自动：未识别玩家行`。
- 多行都匹配或都不匹配：状态为 `自动：未识别玩家行`。
- 匹配到玩家但棋子图标不明确：状态为 `自动：未识别棋色`。
- 任一失败态都不发送 `play`。

## 昵称字形指纹

昵称字形指纹不是整行截图，也不是头像、棋子或财富列截图。它只来自用户确认行的昵称文字区域。

建议规则：

- 截取昵称文字区域，避开左侧头像、右侧棋子/性别/国旗/段位。
- 对文字像素做二值化或边缘化，保留彩色昵称字形和抗锯齿暗边。
- 保存 compact signature，不保存完整截图。
- 运行时对每个候选行做小范围位移容忍匹配。
- 要求最佳分数达到阈值，并且与第二名有明显差距；否则返回未知。

第一版不要求对所有昵称颜色、所有字体效果都做到 OCR 级别识别。目标是让用户确认过的昵称在当前野狐 UI 中跨房间稳定匹配，同时宁可失败也不误发 `play`。

## 棋色图标识别

第一版只识别玩家行附近的黑白棋子图标，不识别整张棋盘。

建议规则：

- 在玩家列表每行中限定棋子图标候选区域。
- 用亮度、饱和度和圆形区域统计区分黑/白。
- 黑棋图标需要满足低亮度占比阈值。
- 白棋图标需要满足高亮度占比阈值，并排除纯背景。
- 两者都不满足时返回未知。

这部分应作为纯函数测试，输入小图或采样像素，输出 `black` / `white` / `unknown`。

## 协议行为

不新增协议行。

`SyncCoordinatorHostSnapshot.PlayColor` 的来源改为：

1. `执黑` 返回 `black`。
2. `执白` 返回 `white`。
3. `自动` 返回当前自动识别结果。
4. 自动识别未知时返回 `null`。

`SyncSessionCoordinator.SendPlayIfSelected(...)` 继续只在 `PlayColor` 非空时发送现有 `play` 消息。

## 安全规则

- 手动 `执黑` / `执白` 永远优先。
- 自动模式只在 Fox mode 生效。
- Fox 标题必须是 `对弈中`；`观战中` 即使匹配到昵称也不发送 `play`。
- 识别结果必须来自当前绑定的 Fox 窗口，不从全局窗口列表猜。
- 不使用上一次成功识别结果冒充当前局面。
- 识别失败不自动落子。
- 用户重新选择昵称后，立即清空旧识别缓存并重新识别。

## 测试要求

自动化测试至少覆盖：

- `执黑` / `执白` 仍生成现有 `play black ...` / `play white ...`。
- `自动` 且识别为黑时生成 `play black ...`。
- `自动` 且识别为白时生成 `play white ...`。
- `自动` 且识别未知时不发送 `play`。
- 非 Fox mode 下选择 `自动` 不发送 `play`。
- Fox 标题为 `观战中` 时，即使命中昵称也不发送 `play`。
- 保存昵称字形指纹后能跨房间匹配正确玩家行。
- 昵称匹配冲突时返回未知。
- 黑白棋子图标识别的阈值边界。
- 重新选择昵称会清空旧缓存。

手工验证至少覆盖：

- 空盘第 0 手时自动识别执黑并发送 `play black ...`。
- 自己执白时不在第 0 手错误发送 `play black ...`。
- 切换到另一间野狐房间后不会沿用上一局识别结果。
- 识别失败时 UI 明确显示失败态，且不会自动落子。
- 后台落子模式下窗口不最小化时仍能识别玩家行与棋色图标。

## 实施切口

建议分两步实现：

1. UI 与状态模型：
   - 三选一棋色模式。
   - 选择、保存、清除野狐身份。
   - 自动模式失败时不发送 `play`。

2. Fox 玩家行识别：
   - 当前窗口玩家列表候选定位。
   - 当前会话身份或已保存昵称字形指纹匹配。
   - 黑白棋子图标识别。

这样第一步可以先锁定协议和 UI 行为，第二步再独立验证实际 Fox 窗口识别可靠性。
