# 野狐自动落子棋色识别设计

日期：2026-05-20

## 背景

readboard 现有自动落子依赖主界面里的 `执黑` / `执白` 单选项。用户需要在野狐对局开始前手动确认自己执哪一方，否则 `play black ...` / `play white ...` 可能不会发送，或发送错误棋色。

本设计只针对：

- `野狐`
- `野狐(后台落子)`

其它平台先保持现状。

本设计已核对：

- `docs/DEVELOPMENT.md`
- `docs/specs/2026-04-21-readboard-fox-title-status-design.md`
- `docs/specs/2026-05-04-sync-session-outbound-send-phase3.md`

相关约束：

- 不新增独立高频 Fox 标题或窗口轮询通道。
- 不改变 readboard 与 LizzieYzy-Next 的 wire protocol。
- `play black ...` / `play white ...` 仍是唯一自动落子棋色输出。
- 识别失败时宁可不自动落子，不猜测棋色。

## 目标

- 让用户可以选择 `自动`，由 readboard 在野狐对局里识别自己是黑棋还是白棋。
- 保留手动 `执黑` / `执白` 作为最高优先级。
- 第一次使用自动模式时，让用户确认并保存自己的野狐昵称或当前玩家身份。
- 后续自动模式尽量免打扰；识别失败时给清楚状态和重新选择入口。

## 非目标

- 不做观战身份识别。
- 不从棋盘黑白子数量反推用户身份。
- 不为了识别昵称引入未经确认的大型 OCR 或外部运行时依赖。
- 不修改 LizzieYzy-Next 的协议解析或同步逻辑。
- 不支持非野狐平台自动识别棋色。

## UI 设计

把现有自动落子棋色单选项调整为三选一：

- `执黑`
- `执白`
- `自动`

行为：

- `执黑`：保持现有行为，发送 `play black ...`。
- `执白`：保持现有行为，发送 `play white ...`。
- `自动`：只在 Fox sync mode 下尝试识别当前用户棋色。

自动模式旁增加只读状态文本，建议文案：

- `自动：已识别执黑`
- `自动：已识别执白`
- `自动：未配置昵称`
- `自动：未识别昵称`
- `自动：未识别棋色`

状态文本只展示当前结果，不改变自动落子条件。

## 首次自动确认

当用户第一次选择 `自动`，且没有已保存的野狐身份时，弹出“选择野狐昵称”窗口。

窗口内容：

- 当前 Fox 右侧玩家列表中的两个玩家候选。
- 如果能读取文本，显示识别到的昵称。
- 如果不能稳定读取文本，显示两行玩家区域截图，让用户选择“上方玩家是我”或“下方玩家是我”。
- 提供手动输入框，用于保存或修正野狐昵称。
- 勾选项：`记住这个昵称，以后自动使用`。

保存内容：

- 用户确认的野狐昵称文本。
- 可选的玩家昵称视觉签名，用于文本读取不可用时匹配同一个昵称区域。

不使用“以后不再提醒”这种反向开关。设置里直接展示当前保存的昵称和重新选择入口。

## 设置入口

参数设置里增加 Fox 自动模式相关项：

- `野狐昵称`
- `重新选择野狐昵称`
- `清除已保存昵称`

如果已保存昵称，用户再次选择 `自动` 时不弹窗，除非当前识别失败并主动点击重新选择，或在设置中清除后重新配置。

## 识别策略

识别流程只在现有 Fox 窗口绑定和同步生命周期内运行，不新增独立轮询线程。

触发时机：

- 用户选择 `自动`
- 开始一键同步
- 开始持续同步
- Fox 房间上下文变化
- 当前自动识别状态为未知时，按现有采样节奏节流重试

步骤：

1. 确认当前模式是 `野狐` 或 `野狐(后台落子)`。
2. 确认当前 Fox 窗口绑定有效。
3. 定位右侧玩家列表区域。
4. 读取两行玩家候选。
5. 用已保存昵称匹配玩家行。
6. 若文本读取不可用，用保存的视觉签名匹配玩家行。
7. 在匹配到的玩家行附近识别黑/白棋子图标。
8. 得出 `black` 或 `white`。

失败处理：

- 匹配不到昵称：状态为 `自动：未识别昵称`。
- 两行都匹配或都不匹配：状态为 `自动：未识别昵称`。
- 匹配到玩家但棋子图标不明确：状态为 `自动：未识别棋色`。
- 任一失败态都不发送 `play`。

## 棋色图标识别

第一版只识别玩家行附近的黑白棋子图标，不识别整张棋盘。

建议规则：

- 在玩家列表每行中限定棋子图标候选区域。
- 用亮度、饱和度和圆形区域统计区分黑/白。
- 黑棋图标需要满足低亮度占比阈值。
- 白棋图标需要满足高亮度占比阈值，并排除纯背景。
- 两者都不满足时返回未知。

这部分应作为纯函数测试，输入小图或采样像素，输出 `black` / `white` / `unknown`。

## 协议行为

不新增协议行。

`SyncCoordinatorHostSnapshot.PlayColor` 的来源改为：

1. `执黑` 返回 `black`。
2. `执白` 返回 `white`。
3. `自动` 返回当前自动识别结果。
4. 自动识别未知时返回 `null`。

`SyncSessionCoordinator.SendPlayIfSelected(...)` 继续只在 `PlayColor` 非空时发送现有 `play` 消息。

## 安全规则

- 手动 `执黑` / `执白` 永远优先。
- 自动模式只在 Fox mode 生效。
- 识别结果必须来自当前绑定的 Fox 窗口，不从全局窗口列表猜。
- 不使用上一次成功识别结果冒充当前局面。
- 识别失败不自动落子。
- 用户重新选择昵称后，立即清空旧识别缓存并重新识别。

## 测试要求

自动化测试至少覆盖：

- `执黑` / `执白` 仍生成现有 `play black ...` / `play white ...`。
- `自动` 且识别为黑时生成 `play black ...`。
- `自动` 且识别为白时生成 `play white ...`。
- `自动` 且识别未知时不发送 `play`。
- 非 Fox mode 下选择 `自动` 不发送 `play`。
- 保存昵称后能匹配正确玩家行。
- 昵称匹配冲突时返回未知。
- 黑白棋子图标识别的阈值边界。
- 重新选择昵称会清空旧缓存。

手工验证至少覆盖：

- 空盘第 0 手时自动识别执黑并发送 `play black ...`。
- 自己执白时不在第 0 手错误发送 `play black ...`。
- 切换到另一间野狐房间后不会沿用上一局识别结果。
- 识别失败时 UI 明确显示失败态，且不会自动落子。
- 后台落子模式下窗口不最小化时仍能识别玩家行与棋色图标。

## 实施切口

建议分两步实现：

1. UI 与状态模型：
   - 三选一棋色模式。
   - 保存/清除野狐昵称。
   - 自动模式失败时不发送 `play`。

2. Fox 玩家行识别：
   - 当前窗口玩家列表候选定位。
   - 昵称或视觉签名匹配。
   - 黑白棋子图标识别。

这样第一步可以先锁定协议和 UI 行为，第二步再独立验证实际 Fox 窗口识别可靠性。
