# 引擎决策落子（`gma`）设计（2026-06-24）

## 状态

已与用户确认，待实施。

## 目标

为 ReadBoard 的自动落子增加持久化的“引擎决策落子”方式。它与既有“一选落子”互斥：前者请求 Host 使用 KataGo `kata-genmove_analyze` 最终落子，后者保持从分析候选第一手落子的既有行为。

此功能仍由 ReadBoard 决定棋色、时间、最大计算量和后台思考；ReadBoard 本身不直接启动或控制 KataGo。

## UI 与配置

- 在自动落子设置附近提供“落子方式”二选一：`一选落子`（默认）与`引擎决策落子`。
- 将选择保存到 `AppConfig` 的 JSON 和下划线 legacy 格式。读取旧配置、字段缺失或非法枚举值时，一律回退为“一选落子”。
- `引擎决策落子`时禁用“首选计算量”输入，但不删除其已保存值；切回“一选落子”后恢复原值和既有行为。
- 已有“后台思考”不改名、不迁移、不新增替代选项；它仍保存为 `PlayPonder`，并继续在启动和设置保存时发送 `playponder on/off`。
- 增加模式相关的中英日韩文案、主题控件集合和布局回归覆盖；禁用的“首选计算量”必须在切回一选时恢复可编辑与原值。

## 协议扩展与兼容

既有消息：

```text
play>black>5 1000 0
```

引擎决策消息：

```text
play>black>5 1000 0 gma
```

- `gma` 是 `genmove_analyze` 的协议缩写，只能作为第三段数值之后的精确 token 解释。
- 不带 `gma` 的消息永远是既有“一选落子”。
- 保留前三个数值及其顺序，旧 Lizzie Host 会忽略末尾 token，因此向后兼容。
- 落子方式改变时发送一条携带当前完整棋色、时间、最大计算量、首选计算量和方式的 `play>`，防止参数与模式先后错配。方式也必须计入重连重发与去重签名，不能因“同色同数值”而吞掉切换。
- `stopAutoPlay` 取消已发送 `play>` 对当前自动落子的授权。同步会话不停止而再次开启自动落子时，即使棋色、数值、方式和房间上下文均未变化，ReadBoard 也必须让后续一次真实识别重新发送完整 `play>`，不能被旧去重签名吞掉。
- Host 收到 `play>... gma` 后要等下一帧已接受的棋盘再启动 GMA；ReadBoard 因此必须让下一次真实识别帧绕过去重，即使棋盘 payload 未变化也要在该 `play>` 之后完整发送。
- 该保证不能通过重放缓存帧或从 `play>` 直接启动 GMA 实现；authoritative frame 仍来自下一次正常棋盘识别。
- 既有 `timechanged`、`playoutschanged`、`firstchanged` 与 `playponder` 消息继续保持原有职责；`timechanged` / `playoutschanged` 在 `gma` 下更新 Host 的下一手原始限制，当前已经开始的搜索不变。所有 `SendPlay`、重连重放和自动落子发送入口都统一携带当前方式。

本设计有意新增该可选 token，作为独立功能扩展；这覆盖旧的自动棋色规格中“本轮不新增 wire protocol”的非目标，但不放宽其他协议兼容约束。

## 数值语义

- `time` 和 `playouts` 均允许空白；协议值使用现有的 `0` 表示未设。
- 在 `gma` 中，`time=0` 表示不限制 `maxTime`，`playouts=0` 表示不限制 `maxVisits`；二者都为 `0` 时由 KataGo 自身配置决定。
- `firstPolicy` 仍保持在线路中以维持旧协议形状，但 `gma` Host 会忽略它。
- 一选落子模式保留现有数值处理和含义。

## 后台思考的生效边界

“后台思考”是 ReadBoard 对 Host 原生 ponder 的授权：

- 勾选：Host 在 `gma` 最终落子后允许 KataGo 原生 ponder 继续，不启动 `kata-analyze`。
- 未勾选：Host 在最终落子后停止/不保留原生 ponder。
- 切换开关不取消正在进行的最终决策；它从该手结束后的后台思考开始生效。关闭已在进行的后台思考时应立即停止。

ReadBoard 的显式“分析/停止” (`noponder`) 和“停止自动落子”则不同：它们取消用户对当前自动落子的授权，Host 必须让待决 GMA 的迟到最终结果失效，即使引擎端的不可取消搜索仍会稍后返回。

## 非目标

- 不在 ReadBoard 添加“对手回合持续显示分析”的开关。
- 不改变棋盘识别、落子坐标、PASS、快照 payload/识别语义或历史恢复。
- 不为非 KataGo 引擎模拟 `gma`。
- 不增加另一个泛化的 genmove 模式。
- 不支持双引擎/引擎 PK 会话中的 `gma` 自动落子；Host 会安全阻止该模式，ReadBoard 不另行增加第二引擎设置。

## 功能完成后的使用说明

本规格不在实现前创建面向使用者的说明文档。全部代码、测试和联调完成后，再依据实际行为在两个维护仓库各自的 `docs/` 下新增对应说明；README 是否增加链接留待后续决定。

说明只面向使用者，以简洁说明和一张对照表为主：区分“一选落子”使用 `kata-analyze` 当前第一候选与“引擎决策落子”接受 `kata-genmove_analyze` 最终着法；写明 GMA 本手仍实时显示候选、胜率、PV、ownership，不在对手回合发 `kata-analyze`，以及“后台思考”控制原生 ponder。表格必须准确呈现两种模式的 `time` / `playouts` / `firstPolicy` 映射，特别是 GMA 中 `0` 或空白代表不传上限、交给 KataGo 配置，而不是秒落子。说明还须列出 KataGo 三项 GTP 能力要求、旧三数值 `play>` 与 `gma` 扩展的兼容、双引擎/PK 限制及“持续对手回合分析”不在本轮范围。不得复制内部 epoch、队列隔离或测试设计。

## 验收

1. JSON、legacy 配置、缺失字段和非法方式都能读取，后两者默认一选落子。
2. `gma` 序列化、模式切换、重连重放、去重签名和旧三数值消息均正确。
3. 数值增量消息在 `gma` 中更新下一手限制；模式、后台思考和首选计算量控件在保存/重启后的状态符合定义。
4. 高 DPI、既有主题和四种语言下新增控件不裁切、不遮挡；禁用/恢复首选计算量可访问且无值丢失。
5. ReadBoard 验证测试通过；与升级后的 Host 联调时，`gma` 在多条 `info` 后仍只由最终着法同步一次，不会重复点击。
